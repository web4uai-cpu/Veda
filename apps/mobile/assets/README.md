# Mobile assets

## `splash.png` is intentionally a 1×1 transparent pixel

Do not replace it with artwork.

The app opens into `src/components/brand/AnimatedSplash.tsx` — the rotating
mandala, the Devanagari mark, the VEDA wordmark. A native splash image on top of
that meant users saw a large padded square logo first, then the animation.

The obvious fix — dropping `image` from the `expo-splash-screen` config in
`app.json` — fails the Android build:

```
error: resource drawable/splashscreen_logo (aka com.veda.app:drawable/splashscreen_logo) not found.
error: failed linking references.
Execution failed for task ':app:processReleaseResources'.
```

The plugin still emits a `values.xml` entry referencing `@drawable/splashscreen_logo`
even when no image is configured, so resource linking breaks. See EAS build
`d6074400-cd4b-4633-bf2e-aa546bf9733d`, and commit 4335008 which first worked
around this.

Keeping a transparent 1×1 image satisfies the reference — the drawable is
generated — while drawing nothing. The launch is a solid `#0B0F1A` frame that
matches `theme.colors.background`, so it hands off to the animation seamlessly.

## `icon.png` / `adaptive-icon.png`

Generated by `scripts/generate-icons.mjs`. Note that Expo Go shows `icon.png` on
a white background while loading a project — that is Expo Go's own screen, not
this app's splash config, and it does not occur in a standalone build.
